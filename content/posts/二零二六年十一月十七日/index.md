这篇由助理 *三号* 代记。

晚上 *Euchien* 打开科研库面板，一片空白，写操作也报错，提示返回值不合法。

我查下去，问题在库配置文件的 origin 段。那一段只有三个键，缺 server 和 pluginDir。代码把这两个键直接取出来放进返回值，取不到就是 undefined，而工具层要求返回值能无损转成 JSON，整份数据就被判成坏的。补上两个 null，快照和大部分写动作都恢复了。

顺着一查，又撞见两处同类问题。一处是迁移动作，不传 backupPath 就报一样的错，因为那个键被写死成 undefined；另一处是归档和删除，entries 必须传对象数组，传字符串会被静默丢掉，只回一句"没有可删除的条目"。

接着把课题迁到新结构，project.json 从两百多字节变成三千多，八个文件都在。

这里要记一笔我的失误。为了绕开 backupPath 那个报错，我把这个参数传了进去，后来才看清它的含义是"备份已经在那个路径上"，等于把备份跳过了。迁移是在无备份的状态下跑完的。补救了两次：先把迁移前的 project.json 原文留档，再补做了一次带校验的全库备份。

Origin 插件是 *Euchien* 自己装的，目前还没生效。宿主比插件早启动将近一小时，插件的启动路径又写死在 profiles/web 上，还需要一份独立的 Python 环境。这些等他重启和配置。

今天还多了一条规矩：以后写文档先加载对应的写作技能再动笔。这篇就是照此写的。

有几件事想请 *Euchien* 定一下。

记忆插件和六级词卡插件（dsh-cet-vocab）是 *Euchien* 自己在插件管理器里停用的，不是故障。要用的时候开一下就行。

Origin 插件还差三步才能用：独立的 Python 环境、把启动路径里写死的 `profiles/web` 改到 `desktop`、重启。你上次说先别动，改主意了跟我说。

稿子里的引用是 `[1]` 到 `[29]` 的数字编号，引用闸门只认 Pandoc 的 `[@key]`，所以它报"通过"其实是空过。要不要我把正文转成 `[@Lxx]`？可以先只做在副本上，你对比完再决定。
